# 여행 선택 경계 정리 (#30 · #31 · #32)

작성일: 2026-11-02

세 이슈는 한 가지 경계에서 나온다. **소비 입력·내역 편집은 여행을 "고르기만" 하고, 여행의 기간·기본 인원·지갑은 여행 화면(`TripEditView`)에서만 고친다.** 그러면 "이 소비가 어느 여행에 속하는가"는 소비 날짜로 판정하는 주어진 조건이 된다.

## #30 기간이 끝난 여행이 계속 뜬다

- 원인: `fetchActiveTrips()`가 정산 여부만 보고 날짜를 보지 않았다.
- 규칙(`TripModel.selectable(from:on:keeping:)`): 고를 수 있는 여행은
  - 정산하지 않았고 **소비 날짜**(`tempDate`)가 기간 안인 여행
  - 편집 중인 기록이 **원래** 묶여 있던 여행 — 기간·정산과 무관하게 남긴다 (정산 완료면 잠긴 채로)
- 기준이 오늘이 아니라 소비 날짜인 이유: 여행 다녀와서 며칠 뒤 영수증을 입력해도 그 여행이 떠야 한다.
- 날짜를 옮겨 이 화면에서 고른 여행이 목록에서 빠지면 선택을 푼다. 사용자가 "여행 아님"을 고른 게 아니므로 날짜를 다시 기간 안으로 돌리면 다시 자동 선택된다.
- 목록이 비면 여행 항목 자체가 렌더되지 않는다 (`SpendView`의 기존 `if !activeTrips.isEmpty`).
- 여행 목록 화면은 `진행 중` / `정산 대기`(기간 끝, 미정산) / `정산 완료`로 나눈다.
- `fetchActiveTrips()`(미정산 전체)는 자동 선택(`trip(containing:)`)과 기존 테스트가 쓰므로 의미를 바꾸지 않고 남긴다.

## #31 '여행 아님'으로 되돌려도 인원이 남는다

- 원인: 풀 때 분담값을 일부러 안 되돌렸다. 여행이 지워진 분담 기록을 편집하는 경우에는 맞지만, 새 소비에서 여행을 골랐다 푸는 흔한 경우까지 덮었다.
- 규칙(`TripShareAutofill`): 여행 선택이 채운 인원·결제자를 기억하고, **그 값 그대로일 때만** 1명·내가 냄으로 되돌린다.

| 경우 | 동작 |
|---|---|
| 새 소비: 여행 선택 → 여행 아님 | 1명 · 내가 냄 |
| 새 소비: 여행 선택 → 인원·결제자 직접 변경 → 여행 아님 | 바꾼 값 유지 |
| 날짜를 옮겨 여행이 풀림 | 위와 같은 규칙 |
| 편집: 여행이 삭제된 분담 기록 → 여행 아님 | 유지 |
| 편집: 여행에 묶인 기록 → 여행 아님 | **유지** (기록에서 불러온 값은 사용자 소유. 분담 블록이 값을 보여주므로 직접 고칠 수 있다) |

마지막 행이 이슈의 "결정 필요" 항목이다. 화면에 보이는 값을 조용히 바꾸지 않는다는 기존 원칙(`SpendingEditDraft`)에 맞춰 유지로 정했다.

## #32 소비 입력은 고르기만

- 여행 블록 아래에 "여행 기간·기본 인원은 설정 › 여행에서 고쳐요" 안내 (`TripModel.editHint`).
- 분담 블록 제목을 "이 소비를 나누는 인원"으로 바꾸고, 여행 기본 인원과 다르면 "이 소비만 3명이에요 · 여행 기본 인원은 4명"을 보여준다.
- 여행의 기간 수정 통로는 `TripEditView` 하나뿐임을 확인했다 (`createTrip`/`updateTrip` 호출처가 그 화면뿐).
- **기간을 줄여 묶인 소비가 밖으로 밀려날 때:** 연결을 자동으로 풀지 않는다(정산 금액이 조용히 바뀐다). 대신
  - 여행 수정 화면: "묶인 소비 N건이 이 기간 밖이에요" 경고
  - 여행 상세: 기간 밖 날짜 묶음에 "· 여행 기간 밖" 표시
- 소비 입력에서 여행 상세로 바로 가는 링크는 넣지 않았다. 소비 입력이 탭 루트라 여행 상세로 가는 내비게이션 경로가 없어서, 안내 문구로 대신한다.
