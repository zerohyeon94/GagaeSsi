# 하루 사용 가능 금액 계산 규칙 (확정)

- **작성일**: 2026-07-08
- **상태**: 확정 (현재 구현 기준 규칙 문서화)
- **최종 개정**: 2026-08-08 (3-13 초과일 판정 — 음수 이월·위시 저금 제외)
- **관련 노션**: [가계씨 — 하루 사용 가능 금액 계산 규칙 확정](https://app.notion.com/38fe5d4a0bac81b68ff9fe6cff42a0a5)
- **관련 코드**: `Core/Utils/BudgetCalculationUtils.swift`, `Core/CoreDataManager.swift`, `Models/BudgetModels.swift`

---

## 1. 목적

월급 · 고정지출 · 급여 기간 · 이월 금액을 기준으로 "오늘 쓸 수 있는 금액"을 계산하는 규칙을 확정한다. 이 문서가 기준(single source of truth)이며, 구현과 어긋나는 부분이 생기면 이 문서를 기준으로 수정한다.

## 2. 용어 정의

| 용어 | 정의 |
|---|---|
| 급여 기간 | 이번 급여일(포함) ~ 다음 달 급여일(미포함) |
| 기본 일일 예산 (`availableAmount`) | 급여 기간 동안 하루에 균등 배분되는 금액 |
| 이월 금액 (`carryOver`) | 전날 잔액이 다음날로 넘어온 금액 (음수 가능) |
| 오늘 가용 금액 (`todayAvailable`) | 오늘 실제로 쓸 수 있는 금액 |

## 3. 계산 규칙

### 3-1. 급여 기간 결정

- 오늘 날짜가 이번 달 급여일 **이상**이면 → 급여 기간 시작 = 이번 달 급여일
- 오늘 날짜가 이번 달 급여일 **미만**이면 → 급여 기간 시작 = 지난달 급여일
- 급여 기간 끝 = 시작일 + 1개월 (총 일수는 달에 따라 28~31일)

### 3-2. 기본 일일 예산

```
기본 일일 예산 = (월급 − 고정비 합계) ÷ 급여 기간 총 일수
```

- **원 단위 내림** (정수 나눗셈)
- 고정비는 결제일과 무관하게 급여 기간 전체에 균등 분배
- 급여 기간 내 모든 날짜에 동일한 기본 예산 적용

### 3-3. 오늘 가용 금액

```
오늘 가용 금액 = 기본 일일 예산 + 이월 금액 합계 − 오늘 소비 합계
```

### 3-4. 이월 규칙

1. **전날 잔액 전액 이월**: 전날의 `todayAvailable`(기본 예산 + 이월 − 소비)이 다음날 이월 금액이 된다.
2. **음수 이월 허용**: 초과 지출 시 음수 잔액도 그대로 이월된다 (다음날 예산에서 차감). → *과소비 페널티가 자연스럽게 반영되는 것이 제품 의도*
   - **예외 (2026-08-07 추가)**: 초과분이 크면 한 번에 차감하지 않고 **부채로 분리해 나눠 갚는다**. → 3-6 참조
3. **누적 연결**: 앱을 며칠 안 열어도 실행 시점에 마지막 기록일 다음날부터 오늘까지 하루씩 순차 생성하며 잔액을 연쇄 이월한다 (`processDailyBudgets(upTo:)`).
4. **멱등성**: 이미 존재하는 날짜는 건너뛰므로 중복 이월되지 않는다.
5. **신규 사용자**: 첫날은 이월 0으로 시작한다.

### 3-5. 설정 변경 시 재계산

- 월급 · 급여일 · 고정비 변경 시: **오늘의 기본 예산만** 새 설정으로 재계산한다.
- 과거 날짜의 예산과 이월 내역은 재계산하지 않는다 (기록 보존).
- 오늘의 이월 금액과 소비 기록은 유지된다.

### 3-6. 초과 소비 상환 계획 (부채 분리)

- **설계 문서**: [초과 소비 상환 계획 설계](superpowers/specs/2026-08-07-overspend-repayment-plan-design.md)
- **관련 코드**: `Models/DebtModels.swift`, `Core/CoreDataManager.swift`

전날 잔액이 음수일 때 다음 규칙을 적용한다 (`BudgetConfig.debtPlanEnabled`가 `true`일 때만):

```
임계값 = 기본 일일 예산 × 10%   (원 단위 내림)

|음수 잔액| < 임계값  → 3-4의 기존 규칙 그대로 (음수 전액 이월)
|음수 잔액| ≥ 임계값  → 이월 0, 초과분을 SpendingDebt로 분리
```

계획이 확정된(`isPlanned == true`) 부채가 있으면 **매일** 다음 금액을 차감한다:

```
상환액 = min(남은 부채, 기본 일일 예산 × 상환비율% ⌊원 단위 내림⌋)
```

- 상환비율은 사용자가 **10~50% 중 5% 단위**로 고른다 (기본 20%).
- 상환액은 `CarryOverSource(amount: −상환액, date == toDate == 그날)`로 기록한다.
  `withdrawFromPool`과 동일한 형태이므로 `recalculateCarryOverChain`(과거 소비 수정 시 `date < cursor`인 소스만 삭제)에서 보존된다.
- **멱등성**: 그날 `DebtRepaymentEntry`가 이미 있으면 건너뛴다.
- **계획 미확정**: 상환액 0. 부채만 쌓이고 사용자가 홈에서 계획을 확정한 날부터 상환이 시작된다.
- **재초과**: 남은 부채에 합산하고 기간만 다시 계산한다 (상환비율은 유지).
- **급여일 정산 (필수)**: 급여 기간이 시작되면 남은 부채를 **그 기간 예산으로 흡수**한다. → 3-7 참조
- **이월 방식(전액/분리)과의 관계**: 부채는 **음수 처리만 대체**한다. 양수 잔액 처리(전액 이월 또는 풀 적립)는 두 모드 모두 기존과 동일하다.
- **모아둔 이월금 풀과의 우선순위**: 소비 저장 시점의 **풀 부족액 충당이 먼저** 동작한다. 충당하면 그날 잔액이 0이 되어 부채가 생기지 않는다.
- **기능 OFF 전환**: 남은 부채를 그날 이월(음수)로 한 번에 반영하고 부채를 종료한다.

### 3-7. 급여일 부채 정산 (무한 지속 차단)

**왜 필요한가.** 부채를 그냥 이월하면, 사용자가 평소 씀씀이를 유지하는 한 **부채가 영원히 줄지 않는다.**
기본 예산 100,000원 · 20% 상환(20,000원)이면 실제로 쓸 수 있는 돈은 80,000원인데, 습관대로 100,000원을 쓰면
매일 20,000원이 초과되어 다시 부채로 합산된다. 상환액과 정확히 상쇄되어 순증이 0이 된다.
(2026-08-07 수치 검증: 부채가 280,000원에서 19일간 전혀 줄지 않음)

**규칙.** 급여 기간 시작일(실효 급여일)에 남은 부채를 그 기간 예산으로 흡수한다.

```
흡수 가능액 = 월급 − 고정비 − 할부            (이보다 많이 흡수하면 하루 예산이 음수가 된다)
흡수액     = min(남은 부채, 흡수 가능액)

기본 일일 예산 = (월급 − 고정비 − 할부 − 흡수액) ÷ 급여 기간 일수
```

- 흡수액과 적용 기간은 `BudgetConfig.absorbedDebtAmount` / `absorbedDebtPeriodStart`에 저장하고,
  **해당 급여 기간에만** 차감한다. 다음 기간에는 자동으로 사라진다.
- 흡수한 만큼 부채를 상환 처리하고(원장 기록 포함) 부채를 종료한다.
- **순서 주의**: 전날 초과분을 부채에 합산한 **뒤에** 흡수해야, 급여일 전날의 초과까지 함께 정산된다.
- 부채가 흡수 가능액보다 크면 감당할 만큼만 흡수하고 나머지는 다음 급여일로 넘긴다.
  하루 예산이 음수가 되지는 않는다.
- 기간당 1회만 일어난다 (`absorbedDebtPeriodStart` 비교로 멱등).

**효과**: 페널티(하루 예산이 줄어듦)는 유지되면서 부채는 매 급여 기간 반드시 정산되고,
"오늘 쓸 수 있는 금액"이 음수로 표시되지 않는다.

### 3-8. 기존 적자의 즉시 전환

부채 전환은 원래 **일자 전환 시점**에만 일어난다. 그래서 상환 계획 기능이 없던 버전에서 적자가 쌓인 채
업데이트하면, `processDailyBudgets`가 "오늘까지 이미 처리됨"으로 조기 종료해
**하루 동안 계속 "오늘 쓸 수 있는 금액 −29만원" 화면을 보게 된다.**

앱 진입 시 오늘 일자에 남아 있는 **전날에서 넘어온 음수 이월**(`date < 오늘`)을 합산해,
임계값(기본 예산 10%) 이상이면 즉시 부채로 전환하고 해당 `CarryOverSource`를 제거한다.

- 오늘 발생한 크레딧·차감(이월금 인출·환급·상환 — `date == 오늘`)은 건드리지 않는다
- 기능이 꺼져 있거나 임계값 미만이면 기존대로 음수 이월로 남긴다

### 3-9. 상환 속도 경고

씀씀이를 줄이지 않으면 어떤 계산 규칙으로도 적자는 줄지 않는다. 앱이 그 사실을 알려준다.

```
상환 중 쓸 수 있는 금액 = 기본 일일 예산 − 하루 상환액
최근 7일 평균 소비 > 위 금액  →  부채가 줄지 않는 상태 (경고)
더 줄여야 하는 금액 = 최근 평균 − 상환 중 쓸 수 있는 금액
```

홈의 부채 카드에 "이 속도면 초과분이 줄지 않아요. 하루 N원씩 더 줄여보세요."를 표시한다.
평균은 오늘을 제외한 최근 7일 기준이다 (오늘은 아직 진행 중).

### 3-10. 캐릭터 상태와 총 가용액

캐릭터 상태(`CharacterState.from`)는 원래 **오늘 소비 ÷ 기본 예산** 사용률만 봤다. 그래서 이월이 −29만원이어도
오늘 소비가 적으면 "여유"가 떴다(2026-08-07 사용자 제보). **총 가용액(`todayAvailable`)이 음수면
사용률과 무관하게 `over`(걱정)** 로 판정한다. 이월금 충당·상환 중이어도 여전히 음수면 `over`가 우선한다.

### 3-11. 모아둔 이월금으로 초과분 갚기

모아둔 이월금(분리 모드 풀)과 부채는 **같은 예산 흐름에 대한 장부**라 그대로 상계할 수 있다.

```
풀 잔액   −= 상환액
남은 부채 −= 상환액
오늘 예산   변화 없음      ← CarryOverSource를 만들지 않는다
```

- 갚을 수 있는 최대 = `min(풀 잔액, 남은 부채)`
- **자동으로 쓰지 않는다.** 홈 부채 카드의 버튼, 상환 계획 팝업의 선상환 토글,
  급여일 프롬프트 — 세 곳 모두 사용자가 직접 선택한다
  (기존 '부족액 충당 제안'과 같은 원칙: 모아둔 돈은 의식적으로 꺼내 쓰는 돈)

**상환 출처 구분 (`DebtRepaymentEntry.source`)**

출처를 구분하지 않으면 "그날 이미 상환했는지" 판정과 홈 표시가 어긋난다.

| 출처 | 오늘 예산 차감 | 그날 매일 상환을 대체하는가 |
|---|---|---|
| `daily` | O (음수 `CarryOverSource`) | — |
| `pool` | X | **아니오** (같은 날 매일 상환도 그대로 일어남) |
| `absorbed` | X (기간 예산에 반영) | 예 |
| `settle` | O | 예 |

홈의 "초과분 상환" 행은 `daily` + `settle`만 합산한다.

### 3-12. 급여일 이월금 사용 확인

급여일 정산(3-7) 시점에 모아둔 이월금이 있으면 **흡수를 보류하고 사용자에게 묻는다.**

- 풀 잔액이 0이면 묻지 않고 바로 흡수한다
- `[이월금으로 먼저 갚기]` → 풀로 상환 후 남은 부채만 기간 예산으로 흡수
- `[이월금은 그대로 두기]` → 풀 보존, 전액 흡수
- 답할 때까지 보류 상태가 유지되므로, 급여일에 앱을 안 열어도 기간 중 언제 들어오든 정산할 수 있다
- 이번 기간에 **새로 생긴** 부채는 대상이 아니다 (`debt.startedAt <= 기간 시작일`로 판정).
  급여일 전날 초과분은 급여일에 부채가 만들어지므로 `<=`를 쓴다

### 3-13. 초과한 날 되짚어보기 (역산)

부채(`SpendingDebt`)에는 누적 금액과 최초 발생일만 있고 **날짜별 발생 내역이 없다.**
별도 발생 원장을 두는 대신 일자별 `DailyBudget`에서 역산한다.

**과거 적자를 떠안고 있는 것과 그날 과소비한 것은 다르다.**

```
그날 배정액 = 기본 일일 예산
            + max(0, 전날 이월)      ← 아껴서 넘어온 돈만
            + 그날 크레딧·차감        ← 이월금 인출·환급(+), 초과분 상환(−)
그날 초과액 = 소비 − 배정액                (양수일 때만)
```

**음수 이월을 배정액에 넣으면 안 된다.** 넣으면 한 번 적자에 빠진 뒤 잔액이 계속 음수라
**그 뒤 모든 날이 초과일로 표시된다.** (2026-08-08 제보: 6,200원 쓴 날이
"258,036원 초과"로 뜨고, 8일 연속 초과 + 합계 2,254,186원 — 같은 적자를 8번 중복 집계.
실제 부채 275,569원과 완전히 동떨어진 값)

- **위시리스트 저금은 초과액에 넣지 않는다.** 쓴 돈이 아니라 모은 돈이라
  되짚어보기에서 과소비로 치면 안 된다 (잔액 계산에는 그대로 반영된다).
  화면에는 "저금 N원은 초과액에 넣지 않았어요"로 따로 표시한다
- 초과액 합계는 **날짜별 과소비의 합**이지 부채 금액과 같지 않다.
  부채에는 임계값·급여일 흡수·상환이 얽혀 있어 단순 합산과 일치하지 않는다
- 부채로 전환되어 이월이 0이 되어도 **초과한 날 자신의 기록은 그대로 남는다**
- 내역 탭 캘린더의 예산 상태 색도 같은 기준(`OverspendAnalyzer.evaluate`)을 쓴다.
  기본 예산만 보면 이월이 두둑한 날을 "초과"로 잘못 표시하고,
  잔액으로 보면 적자 후 모든 날이 "초과"가 된다
- 원장을 쓰지 않은 이유: 원장은 앞으로 생기는 초과만 담을 수 있어
  **이미 쌓여 있는 부채의 출처를 보여주지 못한다.** 역산은 마이그레이션 없이
  과거 데이터에 바로 적용된다. 대신 과거 소비를 수정하면 초과액도 함께 바뀐다

## 4. 예시

### 4-1. 기본 이월 (상환 계획 OFF)

월급 3,000,000원, 고정비 1,000,000원, 급여일 25일, 급여 기간 30일 가정:

- 기본 일일 예산 = (3,000,000 − 1,000,000) ÷ 30 = **66,666원** (내림)
- 1일차: 소비 50,000원 → 잔액 16,666원 → 2일차로 이월
- 2일차: 가용 = 66,666 + 16,666 = 83,332원. 소비 100,000원 → 잔액 **−16,668원**
- 3일차: 가용 = 66,666 − 16,668 = **49,998원** (초과 지출 차감 반영)

### 4-2. 상환 계획 ON

기본 일일 예산 50,000원, 임계값 = 5,000원 가정:

- 1일차: 가용 50,000원, 소비 150,000원 → 잔액 **−100,000원**
- 임계값(5,000원) 초과 → 2일차 이월 0, **부채 100,000원** 생성
- 홈에서 **20%** 선택 → 하루 상환액 = 50,000 × 20% = **10,000원**, 예상 **10일**
- 2일차: 가용 = 50,000 − 10,000(상환) = **40,000원**, 남은 부채 90,000원
- …
- 11일차: 남은 부채 0원 → 완납, 가용은 다시 50,000원

### 4-3. 급여일 정산 (3-7)

기본 예산 100,000원(월 3,000,000 ÷ 30일), 급여일 전날까지 남은 부채 300,000원:

- 급여일: 흡수 가능액 3,000,000원 ≥ 부채 300,000원 → **전액 흡수**, 부채 0원
- 새 기간 기본 예산 = (3,000,000 − 300,000) ÷ 30 = **90,000원**
- 하루 예산이 10,000원 줄어든 형태로 페널티가 반영되고, 화면에 음수가 뜨지 않는다
- 이후에도 습관대로 100,000원을 쓰면 매일 10,000원씩 다시 초과된다 →
  3-9 경고가 "하루 N원씩 더 줄여보세요"를 표시한다

## 5. 알려진 엣지 케이스 (추후 결정 필요)

| 케이스 | 현재 동작 | 비고 |
|---|---|---|
| 급여일 29~31일 + 해당 일자가 없는 달 (예: 2월 31일) | 말일로 clamp + 주말이면 직전 금요일로 보정 | **해결됨** (2026-07-29, `effectivePayday`) |
| 급여일 당일 예산 리셋 | 전날 잔액은 그대로 이월, 남은 **부채는 새 기간 예산으로 흡수** | **해결됨** (2026-08-07, 3-7) |
| 월급보다 고정비가 큰 경우 | 기본 일일 예산이 음수가 됨 | 저장 단계 검증 추가 검토 |
