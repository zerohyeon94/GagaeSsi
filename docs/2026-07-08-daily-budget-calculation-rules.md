## 1. 목적

월급 · 고정지출 · 급여 기간 · 이월 금액을 기준으로 "오늘 쓸 수 있는 금액"을 계산하는 규칙을 확정한다. 이 문서가 기준(single source of truth)이며, 구현과 어긋나는 부분이 생기면 이 문서를 기준으로 수정한다.

## 2. 용어 정의

| 용어 | 정의 |
|---|---|
| 급여 기간 | 이번 급여일(포함) ~ 다음 달 급여일(미포함) |
| 기본 일일 예산 (`availableAmount`) | 급여 기간 동안 하루에 균등 배분되는 금액 |
| 이월 금액 (`carryOver`) | 전날 잔액이 다음날로 넘어온 금액 (음수 가능) |
| 오늘 가용 금액 (`todayAvailable`) | 오늘 실제로 쓸 수 있는 금액 |

## 3. 계산 규칙

### 3-1. 급여 기간 결정

- 오늘 날짜가 이번 달 급여일 **이상**이면 → 급여 기간 시작 = 이번 달 급여일
- 오늘 날짜가 이번 달 급여일 **미만**이면 → 급여 기간 시작 = 지난달 급여일
- 급여 기간 끝 = 시작일 + 1개월 (총 일수는 달에 따라 28~31일)

### 3-2. 기본 일일 예산

```
기본 일일 예산 = (월급 − 고정비 합계) ÷ 급여 기간 총 일수
```

- **원 단위 내림** (정수 나눗셈)
- 고정비는 결제일과 무관하게 급여 기간 전체에 균등 분배
- 급여 기간 내 모든 날짜에 동일한 기본 예산 적용

### 3-3. 오늘 가용 금액

```
오늘 가용 금액 = 기본 일일 예산 + 이월 금액 합계 − 오늘 소비 합계
```

### 3-4. 이월 규칙

1. **전날 잔액 전액 이월**: 전날의 `todayAvailable`(기본 예산 + 이월 − 소비)이 다음날 이월 금액이 된다.
2. **음수 이월 허용**: 초과 지출 시 음수 잔액도 그대로 이월된다 (다음날 예산에서 차감). → *과소비 페널티가 자연스럽게 반영되는 것이 제품 의도*
3. **누적 연결**: 앱을 며칠 안 열어도 실행 시점에 마지막 기록일 다음날부터 오늘까지 하루씩 순차 생성하며 잔액을 연쇄 이월한다 (`processDailyBudgets(upTo:)`).
4. **멱등성**: 이미 존재하는 날짜는 건너뛰므로 중복 이월되지 않는다.
5. **신규 사용자**: 첫날은 이월 0으로 시작한다.

### 3-5. 설정 변경 시 재계산

- 월급 · 급여일 · 고정비 변경 시: **오늘의 기본 예산만** 새 설정으로 재계산한다.
- 과거 날짜의 예산과 이월 내역은 재계산하지 않는다 (기록 보존).
- 오늘의 이월 금액과 소비 기록은 유지된다.

## 4. 예시

월급 3,000,000원, 고정비 1,000,000원, 급여일 25일, 급여 기간 30일 가정:

- 기본 일일 예산 = (3,000,000 − 1,000,000) ÷ 30 = **66,666원** (내림)
- 1일차: 소비 50,000원 → 잔액 16,666원 → 2일차로 이월
- 2일차: 가용 = 66,666 + 16,666 = 83,332원. 소비 100,000원 → 잔액 **−16,668원**
- 3일차: 가용 = 66,666 − 16,668 = **49,998원** (초과 지출 차감 반영)

## 5. 알려진 엣지 케이스 (추후 결정 필요)

| 케이스 | 현재 동작 | 비고 |
|---|---|---|
| 급여일 29~31일 + 해당 일자가 없는 달 (예: 2월 31일) | `Calendar` overflow로 다음 달 초로 밀림 | "말일 처리" 규칙 확정 필요 (예: 그 달의 말일로 보정) |
| 급여일 당일 예산 리셋 | 새 급여 기간 기본 예산으로 계산되지만 전날 잔액도 이월됨 | 급여일에 이월을 리셋할지 유지할지 결정 필요 (현재: 유지) |
| 월급보다 고정비가 큰 경우 | 기본 일일 예산이 음수가 됨 | 저장 단계 검증 추가 검토 |
