# 화면 디자인: 사용자 카테고리 추가·수정·삭제 (#35)

- 기획서: `docs/기획/35-custom-spending-category.md`
- 작성: 디자인팀, 2026-10-29
- 디자인 링크: 없음 (이 문서가 원본)

이 문서는 기획서 3·5장을 화면으로 옮긴 명세다. 기획서에 없는 것은 맨 끝 "기획 밖 제안"에만 적었다.
화면 문구는 기획서 9장 용어를 따른다: "기본", "내가 만든 카테고리", "카테고리" ("분류"·"태그"는 쓰지 않음).

## 0. 지금 쓰고 있는 디자인 규칙 (코드에서 읽은 것)

별도 디자인 시스템 문서가 없어서 기존 화면 코드에서 읽어 정리했다. 새 화면은 이 규칙을 그대로 따른다.

| 항목 | 규칙 | 출처 |
|---|---|---|
| 배경 | 화면 `Color.gagaeBackground`, 카드 `gagaeCardBackground`, 입력칸 `gagaeSurface`, 안 고른 칩 `gagaeSurfaceAlt`/`gagaeSurface` | `DesignSystem.swift` |

## 1. 카테고리 색상 팔레트 (신규 토큰)

### 1-1. 왜 새 토큰이 필요한가
- 기획 7장: 사용자 색은 `Color.adaptive(light:dark:)` 토큰으로, 라이트·다크 모두 칩 글자(흰색)가 읽혀야 하고 내장 색과 겹치지 않아야 한다.
- 내장 7색은 `Color(red:green:blue:)` 고정값이고 모두 **밝은 파스텔 톤**이다(식비 주황, 교통 하늘, 카페 갈색, 쇼핑 자홍, 의료 민트, 여가 보라, 기타 회색).
- 그래서 사용자 팔레트는 **깊은 톤**으로 잡는다. 색상(hue)이 비어 있는 자리(빨강·노랑·연두·청록)를 먼저 채우고, 가까운 hue는 밝기 차이로 구분한다.

### 1-2. 팔레트 (8색, 이 순서로 보여준다)

`DesignSystem.swift`에 `UserCategoryColor` enum(`String` rawValue, `CaseIterable`)으로 정의한다. 저장은 rawValue 키로 한다(hex를 저장하지 않음, 나중에 값을 다듬어도 기록이 따라온다).

| 키 | 이름(접근성 라벨) | light | dark | 흰 글자 대비(추정, light / dark) | 가까운 내장 색과의 구분 |
|---|---|---|---|---|---|
| `rose` | 장미 | `#C2255C` | `#D6336C` | 5.7 / 4.6 | 빨강 계열 내장 없음 |
| `mustard` | 겨자 | `#8A6500` | `#946C00` | 5.3 / 4.8 | 노랑 계열 내장 없음, 카페(밝은 갈색)보다 훨씬 어둡고 노랗다 |
| `olive` | 올리브 | `#5B7A16` | `#637F1A` | 4.9 / 4.6 | 연두 계열 내장 없음 |
| `forest` | 숲 | `#2E7D32` | `#34843A` | 5.1 / 4.6 | 의료(밝은 민트)보다 어둡고 노란 쪽 초록 |
| `teal` | 청록 | `#0F7C78` | `#12807C` | 5.0 / 4.8 | 청록 계열 내장 없음 |
| `ocean` | 바다 | `#00739E` | `#0A7AA6` | 5.3 / 4.8 | 교통(밝은 하늘)보다 훨씬 진하다 |
| `navy` | 남색 | `#3A55A0` | `#4560AC` | 7.0 / 6.0 | 교통·여가 사이 hue, 둘보다 어둡다 |
| `plum` | 자두 | `#8E3B8A` | `#9C4898` | 6.6 / 5.5 | 쇼핑(밝은 자홍)보다 어둡다 |

- 기준: **흰 글자 13pt bold 대비 4.5:1 이상** (WCAG AA 본문 기준). 위 대비 값은 디자인팀 손계산 추정치다. 구현 때 실제 값으로 한 번 확인하고, 4.5 미만이면 dark 값을 light 쪽으로 조금 어둡게 당긴다(밝게 하면 흰 글자가 안 읽힌다).
- dark 값은 어두운 배경(`#221C20`) 위에서 칩 면이 묻히지 않을 만큼만 밝혔다.
- 기본 선택값: 새 카테고리 추가 시 **아직 안 쓴 색 중 첫 번째**를 미리 고른다. 8색을 다 쓰면 `rose`부터 다시(사용자 카테고리는 20개까지라 색은 겹칠 수 있다 — 이름·이모지로 구분되므로 막지 않는다).
- 칩 선택 배경, 목록 원(`opacity(0.13)`), 통계 점·도넛 조각 모두 같은 토큰을 쓴다.

### 1-3. 표시용 공통 모델 (개발팀 참고)
화면은 내장/사용자를 구분하지 않고 **이름·이모지·색** 세 가지만 받는다. 모든 화면이 `category.emoji / .name / .color`처럼 같은 방식으로 읽게 해 두면 아래 2~8장 화면 변경이 "목록 출처만 바꾸기"로 끝난다. 저장 방식(ID 참조 등)은 개발팀이 정한다.

## 2. 설정 > 데이터 > "카테고리 관리" 진입 행

**위치**: `SettingsView.dataSection` 맨 위, "항목 이름 정리" 위 (기획 3-1).

```
데이터
┌──────────────────────────────────────────┐
│ [🗂️] 카테고리 관리            3개   ›   │  ← 신규
│ ─────                                    │
│ [🏷️] 항목 이름 정리                  ›   │
│ [📤] 데이터 내보내기          CSV    ›   │
│ [🗑️] 데이터 초기화                   ›   │
└──────────────────────────────────────────┘
```

- `settingRow(iconBg:, iconContent: Text("🗂️").font(.system(size: 15)), label: "카테고리 관리", rightText:)`.
- iconBg: 기존 설정 행들처럼 아이콘 배경색 하나를 쓴다. `Color(hex: "#E79A3C")`(주황 계열, 데이터 섹션의 보라·하늘·빨강과 겹치지 않음). 설정 행 아이콘 배경은 지금도 행마다 `Color(hex:)`로 두는 관례라 그대로 따른다.
- rightText: 사용자 카테고리 수. 0개면 `"기본 7개"`, 1개 이상이면 `"\(n)개"`.
- 아래 `rowDivider` 추가.

| 상태 | 표시 |
|---|---|
| 기본 | 위 그림 |
| 사용자 카테고리 0개 | 우측 "기본 7개" |
| 큰 글씨 | 기존 행과 같음 (우측 글은 짧아서 줄바꿈 없음) |

## 3. 카테고리 관리 화면 (`CategoryManageView`, 신규)

### 3-1. 구성

```
‹ 설정        카테고리 관리                 ⊕
──────────────────────────────────────────────
 기본                                         
┌──────────────────────────────────────────┐
│ (🍱 식비)(🚌 교통)(☕️ 카페)(🛍️ 쇼핑)      │
│ (💊 의료)(🎬 여가)(💸 기타)               │
│ 기본 카테고리는 바꾸거나 지울 수 없어요     │
└──────────────────────────────────────────┘
 내가 만든 카테고리                     3/20  
┌──────────────────────────────────────────┐
│ (🐶) 반려동물                  12건   ›   │
│ (🎁) 경조사                     3건   ›   │
│ (📺) 구독                       0건   ›   │
├──────────────────────────────────────────┤
│        ＋ 카테고리 추가                   │
└──────────────────────────────────────────┘
 이름·이모지·색을 바꾸면 지난 기록에도 바로 반영돼요.
 예산·이월 계산에는 영향이 없어요.
```

- **화면 틀**: `List` + `.listStyle(.insetGrouped)` + `.scrollContentBackground(.hidden)` + 배경 `Color.gagaeBackground`, 행 배경 `.listRowBackground(Color.gagaeCardBackground)`.
  - 이유: 기획 5-4가 "목록 스와이프로 삭제"를 요구하고, iOS 기본 `swipeActions`는 `List` 안에서만 동작한다. 앱 첫 `List` 사용이라 아래 6장 디자인 시스템 변경에 적었다.
- **내비게이션 바**: 제목 "카테고리 관리", inline, 바 배경 `gagaeBackground`(고정비 관리와 같음). 오른쪽 `plus.circle.fill` 20pt `gagaePinkDark` → 추가 시트. 20개면 비활성(`gagaeTextTertiary`).
- **기본 섹션** (헤더 "기본", 기존 섹션 헤더 스타일 11.5 bold `gagaeTextSecondary` uppercase)
  - 7개를 **줄바꿈 칩 묶음**(흐름 배치)으로 한 행에 보여준다. 칩 모양은 소비 기록 칩의 "미선택" 모양 그대로(`gagaeSurfaceAlt` + 테두리), 이모지 14 + 이름 13 medium `gagaeTextSecondary`. 앞에 색 점 6pt(`category.color`)를 붙여 차트 색을 알 수 있게 한다.
  - 탭해도 반응 없음(버튼 아님). VoiceOver: "식비, 기본 카테고리".
  - 아래 caption 12 `gagaeTextTertiary`: "기본 카테고리는 바꾸거나 지울 수 없어요".
  - 7행 목록 대신 칩 묶음을 쓴 이유: 읽기 전용 7개가 화면 절반을 차지하면 정작 손대는 "내가 만든 카테고리"가 첫 화면 밖으로 밀린다. 기획의 "읽기 전용, 기본 표시"는 섹션 이름과 안내 문구로 지킨다.
- **내가 만든 카테고리 섹션** (헤더 "내가 만든 카테고리", 오른쪽 `"\(n)/20"` 11.5 `gagaeTextTertiary`)
  - 행: 원 34(`color.opacity(0.13)`) + 이모지 16 → 이름 15 medium `gagaeText`(1줄, 말줄임) → Spacer → 사용 건수 13 `gagaeTextSecondary` ("12건") → chevron 12 `gagaeTextTertiary`. 세로 패딩 10, 행 전체 탭 영역(`contentShape`).
  - 탭 → 편집 시트(4장).
  - 왼쪽 밀기(trailing swipe) → 빨간 "삭제" 버튼(`role: .destructive`, `trash` 아이콘) → 삭제 확인(5장). `allowsFullSwipe: false` (끝까지 밀어도 바로 지우지 않고 확인을 거친다).
  - 순서: 만든 순서(기획 4장, 드래그 정렬 없음). 편집 모드(`EditButton`)는 두지 않는다.
  - 섹션 마지막 행: "＋ 카테고리 추가" 버튼 행. 가운데 정렬, `plus` 13 semibold + 15 semibold, `gagaePinkDark`. 툴바 ⊕와 같은 동작(목록 끝에서 바로 누를 수 있게).
- **하단 안내 (섹션 footer)**: caption 12 `gagaeTextTertiary` 두 줄 (위 그림).

### 3-2. 상태

| 상태 | 표시 |
|---|---|
| 빈 화면 (사용자 카테고리 0개) | 내가 만든 섹션에 빈 상태 행: 이모지 "🐷" 32 + "아직 만든 카테고리가 없어요"(15 semibold `gagaeText`) + "반려동물, 육아, 구독처럼 자주 쓰는 지출을\n카테고리로 만들어 보세요"(13 `gagaeTextSecondary`, 가운데). 그 아래 "＋ 카테고리 추가" 행은 그대로. 헤더 카운트 "0/20" |
| 로딩 | CoreData 동기 조회라 로딩 표시 없음. `onAppear`와 카테고리 변경 이벤트에서 다시 읽는다 |
| 20개 도달 | 툴바 ⊕ 비활성, "＋ 카테고리 추가" 행 비활성(글자 `gagaeTextTertiary`) + 바로 아래 caption "카테고리는 20개까지 만들 수 있어요"(`gagaeWarning` 아님, `gagaeTextSecondary` — 오류가 아니라 안내라서). 헤더 "20/20" |
| 오류 (목록 조회 실패) | 빈 상태 대신 "카테고리를 불러오지 못했어요" + "다시 시도" 텍스트 버튼(`gagaePinkDark`). 기본 섹션은 코드 상수라 항상 보인다 |
| 삭제 후 | 행이 기본 애니메이션으로 빠지고 하단 토스트 "‘반려동물’을 삭제했어요" (기록이 있었으면 "기록 12건을 기타로 옮겼어요"). 토스트는 `SpendingTitleCleanupView` 토스트 재사용, 2초 |
| 긴 글 | 이름 최대 10자라 한 줄에 들어간다. 그래도 `lineLimit(1)` + 말줄임, 건수는 `fixedSize`로 잘리지 않게 우선 |
| 큰 글씨 | 행은 `HStack` 그대로, 이름이 먼저 말줄임된다. 건수는 "9,999건"까지 고려해 최소 폭 확보. 기본 칩 묶음은 흐름 배치라 줄 수만 늘어난다 |
| 다크 | 모든 색이 adaptive 토큰. 원 배경 `opacity(0.13)`은 다크에서 옅으므로 그대로 둔다(기존 목록 행과 같은 처리) |

### 3-3. 접근성
- 행 VoiceOver: "반려동물, 내가 만든 카테고리, 기록 12건, 버튼". 커스텀 액션 "삭제"(`accessibilityActions`) — 스와이프를 못 쓰는 사용자도 지울 수 있게.
- 터치 영역: 행 높이 최소 44pt.

## 4. 카테고리 추가·수정 시트 (`CategoryEditSheet`, 신규)

같은 시트를 `mode: .add / .edit(category)`로 쓴다(고정비 `FixedExpenseEditView(mode:)`와 같은 방식).

### 4-1. 구성

```
취소          카테고리 추가                   
──────────────────────────────────────────────
         ┌────────────────────┐               
         │ (🐶 반려동물)       │  ← 미리보기    
         └────────────────────┘               
         선택된 칩  ·  안 고른 칩 두 모양       
┌──────────────────────────────────────────┐
│ 이름                              5/10    │
│ ┌──────────────────────────────────────┐ │
│ │ 반려동물                              │ │
│ └──────────────────────────────────────┘ │
│ ⚠︎ 이미 있는 카테고리 이름이에요            │
├──────────────────────────────────────────┤
│ 이모지                                    │
│ [💸][🐶][👶][🎁][📺][💇][🍺][🏠]          │
│ [📚][💪][✈️][🎮][🚗][🧾][💝][⌨️ 직접]    │
├──────────────────────────────────────────┤
│ 색                                       │
│ (●)(●)(●)(●)(●)(●)(●)(●)                  │
└──────────────────────────────────────────┘
┌──────────────────────────────────────────┐
│               저장하기                    │  ← GagaePrimaryButton
└──────────────────────────────────────────┘
         카테고리 삭제                          ← 수정 모드만
```

- **틀**: `NavigationStack` + `ScrollView` + 배경 `gagaeBackground`. 제목 "카테고리 추가" / "카테고리 수정". 왼쪽 툴바 "취소"(`gagaePinkDark`). `presentationDetents([.large])`, 드래그 표시줄 보임.
  - 수정 중 바뀐 게 있으면 아래로 끌어 닫기를 막고(`interactiveDismissDisabled(isDirty)`) "취소"를 누르면 "수정한 내용을 버릴까요?" 확인(버리기 destructive / 계속 수정). 기획 5-4 "취소하면 아무것도 바뀌지 않는다"를 지키면서 실수로 날리지 않게.
- **미리보기** (카드 위, 가운데): 소비 기록 화면 칩과 **같은 컴포넌트**(7장 `CategoryChip`)를 선택 모양·미선택 모양 두 개 나란히. 이름이 비면 "카테고리" 자리글(흐린 글자)로 채운다. 입력할 때마다 즉시 바뀐다.
- **카드 1: 이름**
  - 라벨 "이름" `gagaeFootnote` `gagaeTextSecondary`, 오른쪽 글자수 `"\(n)/10"` `gagaeCaption` `gagaeTextTertiary` (10이면 `gagaePinkDark`).
  - 입력칸: `gagaeSurface`, r12, 높이 46, 포커스 시 `gagaePinkDark` 1.8 테두리 (소비 기록 내용칸과 같음). 자리글 "예: 반려동물".
  - 추가 모드는 시트가 뜨면 0.3초 뒤 자동 포커스(`MonthlyAmountConfirmView`와 같음). 수정 모드는 자동 포커스 안 함.
  - 10자에서 입력을 멈춘다(기획 5-3). 글자수는 사용자가 보는 글자(grapheme) 기준.
  - 키보드 return = "완료"(키보드만 내림).
- **카드 2: 이모지**
  - 추천 이모지 15개 + "직접" 1칸 = 8열 2줄 그리드(`LazyVGrid`, 칸 40×40, r10). 추천: 💸(기본값) 🐶 👶 🎁 📺 💇 🍺 🏠 📚 💪 ✈️ 🎮 🚗 🧾 💝.
    - 추천 목록 기준: 기획서 1장의 예(반려동물·육아·경조사·구독·미용·술자리) + 자주 쓰는 생활 지출. 내장 7개 이모지는 넣지 않아 헷갈림을 줄였다(💸만 기획서가 정한 기본값이라 둔다).
  - 고른 칸: `gagaePinkLight` 배경 + `gagaePinkDark` 2pt 테두리. 안 고른 칸: `gagaeSurface`.
  - "직접" 칸(⌨️, 아래 "직접" 9pt 글자) → 칸이 입력 모드로 바뀌어 작은 입력칸이 포커스된다. 이모지 키보드로 바로 열 수는 없어서(iOS 제약) 자리글 "🙂 이모지 키보드로 하나 골라요".
    - 입력 규칙(기획 7장): 들어온 글에서 **첫 번째 이모지 1개만** 남긴다. 이모지가 없으면(일반 글자만) 적용하지 않고 칸 아래 caption `gagaeDanger` "이모지만 넣을 수 있어요"를 1.5초 보여준 뒤 이전 이모지 유지.
    - 직접 넣은 이모지는 "직접" 칸 자리에 그 이모지로 표시되고 선택 상태가 된다.
- **카드 3: 색**
  - 1장 팔레트 8색을 원 32pt로 한 줄(간격 `GagaeSpacing.sm`, 좁은 화면은 `ViewThatFits`로 4×2 두 줄).
  - 고른 색: 원 안에 흰 `checkmark` 13 bold + 바깥 3pt `gagaeCardBackground` 간격 + 2pt 같은 색 테두리(링). 색만으로 구분하지 않도록 체크 표시를 꼭 넣는다.
  - VoiceOver 라벨: 팔레트 이름("장미", "겨자"…), 선택 시 "선택됨".
- **저장 버튼**: `GagaePrimaryButton("저장하기", isEnabled:)`, 카드 아래 16 간격. 수정 모드에서 바뀐 게 없으면 비활성.
- **삭제 버튼 (수정 모드만)**: 저장 버튼 아래 24 간격, 텍스트 버튼 "카테고리 삭제" 15 semibold `gagaeDanger`, 가운데. 누르면 5장 확인.

### 4-2. 저장 가능 조건과 안내 문구 (기획 5-3)

| 조건 | 저장 버튼 | 이름 칸 아래 안내 (caption 12) |
|---|---|---|
| 이름 비었거나 공백뿐 | 비활성 | 없음 (처음부터 빨간 글을 띄우지 않는다) |

| 10자 도달 | 활성 가능 | 글자수 "10/10"만 강조 (입력이 멈추므로 별도 문구 없음) |
| 이모지 미선택 | 해당 없음 (항상 💸 기본값이 있다) | — |

- 중복 검사는 입력이 바뀔 때마다 바로 한다(가벼운 문자열 비교).

## 5. 삭제 확인

목록 스와이프 "삭제"와 편집 시트 "카테고리 삭제"가 같은 확인을 띄운다. iOS 기본 `.alert`(앱의 다른 되돌릴 수 없는 동작과 같은 방식).

| 경우 | 제목 | 메시지 | 버튼 |
|---|---|---|---|
| 쓴 기록 0건, 묶인 페이백 0개 | "‘구독’ 카테고리를 삭제할까요?" | "삭제하면 되돌릴 수 없어요." | 삭제(destructive) / 취소 |
| 쓴 기록 N건 | "‘반려동물’ 카테고리를 삭제할까요?" | "기록 12건은 ‘기타’로 옮겨져요.\n같은 이름으로 다시 만들어도 옮겨진 기록은 돌아오지 않아요." | 삭제(destructive) / 취소 |
| 기록 N건 + 페이백 M개 | 〃 | "기록 12건과 페이백 1개의 묶음은 ‘기타’로 옮겨져요.\n같은 이름으로 다시 만들어도 옮겨진 기록은 돌아오지 않아요." | 〃 |

- 페이백 수는 기간형 페이백 중 이 카테고리에 묶인 것만 센다(기획 5-4).
- 건수는 확인창을 띄우는 순간 센다(동기 조회, 로딩 없음).
- 삭제 성공: 편집 시트에서 지웠으면 시트를 닫고 관리 화면에서 토스트(3-2). 실패: `.alert("삭제하지 못했어요", message: "다시 시도해 주세요")`, 목록은 그대로.

## 6. 디자인 시스템 변경 (이유)

1. **`UserCategoryColor` 팔레트 8색 추가** (`DesignSystem.swift`, `Color.adaptive`) — 기획 7장 요구. 내장 색이 밝은 톤이라 사용자 색은 깊은 톤으로 두어 통계 차트에서 섞이지 않게 했고, 흰 글자 대비 4.5:1을 기준으로 삼았다.
2. **`CategoryChip` 공용 컴포넌트로 묶기** — 지금 카테고리 칩이 `SpendView`·`HistorySpendEditView`·`PaybackSheets` 세 곳에 조금씩 다른 크기(12/13pt, 선택색 카테고리색/분홍)로 따로 있다. 사용자 카테고리가 세 곳에 똑같이 나와야 하고 이모지 폭 처리(7-3)도 같아야 해서 한 컴포넌트로 모은다. 모양은 가장 많이 보는 `SpendView` 칩 기준. 페이백 칩만 "선택 = `gagaePinkDark`" 변형을 유지한다(페이백 화면의 다른 선택 요소와 맞추기 위해).
3. **카테고리 관리 화면에 `List(.insetGrouped)` 첫 사용** — 기획의 스와이프 삭제를 iOS 기본 동작으로 주려면 `List`가 필요하다. 배경·행 색은 토큰으로 덮어 다른 설정 하위 화면과 같은 느낌을 유지한다.

## 7. 기존 화면 변경

모든 곳에서 순서는 **내장 7개 → 사용자 카테고리(만든 순서)** (기획 3-5).
카테고리 목록이 바뀌면(`AppEventBus`의 새 트리거, 예: `categoryChangedTrigger`) 열려 있는 화면도 다시 읽는다(완료 기준 1).

### 7-1. 공용 칩 `CategoryChip` (6-2)

```
선택:   [🐶 반려동물]   배경 category.color, 글자 흰색 13 bold
미선택: [🐶 반려동물]   배경 gagaeSurfaceAlt, 글자 gagaeTextSecondary 13 medium, 테두리 gagaeDivider 1.5
추가:   [＋ 추가]       배경 투명, 테두리 gagaePinkDark 1.5 점선(dash 3,2), 글자·아이콘 gagaePinkDark 13 semibold
```

- 패딩 가로 13 / 세로 7, Capsule, 이모지-이름 간격 5.
- **이모지 칸 고정 폭** (기획 7장 "칩 모양이 깨지지 않게"): 이모지를 `frame(width: 18)` 가운데 정렬, `lineLimit(1)`, 넘치면 잘림. 저장 단계에서 이모지 1개로 막지만, 옛 데이터나 예외 값이 와도 칩 높이·폭이 흔들리지 않게 한 번 더 막는다. 이모지 값이 비었으면 💸로 보인다.
- 이름: `lineLimit(1)`, `fixedSize()` (가로 스크롤 줄 안이라 말줄임 대신 전체 표시, 최대 10자).
- VoiceOver: "반려동물, 선택됨" / "추가, 새 카테고리 만들기".

### 7-2. 소비 기록 (`SpendView.categoryField`)

```
🏷 카테고리
(🍱 식비)(🚌 교통)(☕️ 카페)…(💸 기타)(🐶 반려동물)(🎁 경조사)[＋ 추가] →
```

- 칩 줄 끝에 "＋ 추가" 칩 (기획 5-1). 탭 → 4장 시트(추가 모드).
- 저장하면 시트가 닫히고 **방금 만든 칩이 선택된 채로**, 가로 스크롤이 그 칩으로 이동(`ScrollViewReader.scrollTo`, 애니메이션 0.2s). 입력 중이던 내용·금액은 그대로.
- 취소하면 이전 선택 유지.
- 사용자 카테고리가 20개면 "＋ 추가" 칩을 숨긴다(비활성 칩을 두면 왜 안 눌리는지 설명할 자리가 없다. 안내는 관리 화면에서).
- 선택된 칩이 삭제된 카테고리를 가리키면 "기타"가 선택된 것으로 보인다(기획 7장). 빈 칩·크래시 없음.
- 자동완성 추천 칩(`suggestionChips`)의 이모지도 사용자 카테고리 이모지로. 삭제된 카테고리면 💸.
- 큰 글씨/긴 글: 가로 스크롤이라 칩이 늘어나기만 한다. 줄 높이는 칩 높이 하나로 고정.

### 7-3. 내역 수정 (`HistorySpendEditView`)
- 카테고리 칩을 `CategoryChip`으로 교체, 사용자 카테고리 이어 붙임. "＋ 추가"는 **넣지 않는다**(기획 5-1은 소비 기록 화면에만 둔다).
- 수정 중인 기록의 카테고리가 지워졌다면 "기타" 칩이 선택돼 보인다. 저장하면 기타로 저장.
- 이름이 바뀐 카테고리의 기록은 새 이름 칩이 선택돼 보인다.

### 7-4. 목록 행 (소비 기록 오늘 목록, 내역, 여행 상세, 초과 내역)
- `SpendView` 오늘 목록, `HistoryView`, `TripDetailView`, `OverspendHistoryView`의 원 아이콘(`color.opacity(0.13)` + 이모지)과 제목 대체 글(제목이 비면 카테고리 이름)에 사용자 카테고리 값을 쓴다. 모양 변화 없음.
- 원 안 이모지도 7-1과 같이 한 글자로 고정.

### 7-5. 통계 (`StatsView` 카테고리별 지출, `CategoryDetailView`)
- 행의 색 점·이모지·이름, 도넛 조각 색에 사용자 카테고리 값.
- **긴 글 대응 (변경)**: 지금 행은 이름이 줄어들지 않는다. 10자 이름 + "₩1,234,567" + "100%" + chevron이 가장 좁은 화면에서 넘치므로, 이름 `Text`에 `lineLimit(1)` + `truncationMode(.tail)`, 금액에 `layoutPriority(1)`을 준다. 금액은 절대 잘리지 않는다.
- 도넛 조각이 많아지는 경우: 지금처럼 모든 카테고리를 조각으로 그린다(조각 묶기는 기획 밖, 9장).
- `CategoryDetailView` 제목은 "🐶 반려동물" 형태 그대로, 내비 제목 inline이라 10자도 한 줄.
- 이름을 바꾸면 같은 달 통계가 새 이름 한 줄로 합쳐 보인다(옛 이름 행이 따로 남지 않는다 — 완료 기준 3).
- 빈 화면: 지금 "기록이 없어요" 그대로.

### 7-6. 페이백 (`PaybackSheets` 묶을 카테고리, `PaybackListView`)
- "소비 자동 묶기" 칩 줄: `안 씀` → 내장 7 → 사용자 카테고리. `CategoryChip`의 페이백 변형(선택 = `gagaePinkDark`). "＋ 추가" 없음.
- 묶인 카테고리가 지워져 기타로 옮겨졌다면 "💸 기타"가 선택돼 보인다.
- 목록의 연결 표시에도 현재 이름·이모지.

### 7-7. CSV 내보내기
- 화면 변화 없음. "카테고리" 열에 **현재 이름**이 들어간다(기획 3-5).

### 7-8. 데이터 초기화 확인 시트 (`SettingsView.confirmSheet`)
- 문구를 "모든 소비 기록과 예산 설정이\n영구적으로 삭제됩니다." → **"모든 소비 기록, 예산 설정, 내가 만든 카테고리가\n영구적으로 삭제됩니다."** (기획 3-6. 사용자가 지워지는 범위를 알 수 있게).

## 8. 상호작용 흐름 요약

```
설정 ─▶ 카테고리 관리 ─┬─ ⊕ / ＋카테고리 추가 ─▶ 추가 시트 ─ 저장 ─▶ 목록 끝에 추가 (+모든 칩 갱신)
                      ├─ 행 탭 ─▶ 수정 시트 ─┬─ 저장 ─▶ 목록·과거 기록 새 이름
                      │                      └─ 카테고리 삭제 ─▶ 확인 ─▶ 기타로 이동 + 토스트
                      └─ 행 스와이프 삭제 ─────────────────▶ 확인 ─▶ 기타로 이동 + 토스트

소비 기록 ─▶ [＋ 추가] 칩 ─▶ 추가 시트 ─ 저장 ─▶ 기록 화면 복귀, 새 칩 선택됨
```

- 햅틱: 저장 성공 `.success`, 저장 실패 `.error`, 삭제 확정 `.warning`.
- 애니메이션: 칩 선택 `easeInOut 0.12`(기존), 목록 추가·삭제 `List` 기본.

## 9. 기획 밖 제안 (이번 범위 아님, 결정은 기획팀·Zero)

1. **통계 도넛 "그 외" 묶기** — 사용자 카테고리가 많아지면(최대 27개) 도넛 조각이 가늘어지고 같은 색이 반복될 수 있다. 비중 3% 미만은 "그 외" 한 조각으로 묶는 안. 행 목록은 그대로 두고 차트만 묶는다.
2. **내장 7색의 다크 대응·대비 보정** — 내장 색은 `Color(red:green:blue:)` 고정값이라 다크 모드 대응이 없고, 흰 글자 대비가 2~3:1 수준이다(식비 주황 등). 이번엔 기획 범위 밖이라 손대지 않았다. 나중에 `Color.adaptive`로 옮기면서 대비를 맞추는 안.
3. **기타 기록에서 바로 카테고리 만들기** — 내역 수정 화면에도 "＋ 추가" 칩을 두면 "기타 쏠림"을 한 건씩 정리할 때 편하다. 기획 5-1은 소비 기록 화면에만 두기로 해서 이번엔 넣지 않았다.
