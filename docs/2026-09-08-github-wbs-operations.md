# GitHub 이슈 기반 WBS 운영 규칙

작성일: 2026-09-08

## 왜 만드는가

지금까지 개발 진행은 커밋과 `docs/superpowers/plans/` 계획 문서에만 남고, GitHub 이슈는
2025년 7월 이후 갱신이 끊겼다. 열린 이슈 4개 중 2개(#4 날짜 선택, #9 알림)는 이미 구현이
끝났는데도 열려 있었고, 마일스톤 마감일도 모두 지났다.

원인은 "상태를 적을 곳"이 없었기 때문이다. 이슈는 open/closed 두 값뿐이라 **진행중과 보류를
구분할 수 없다.** 그래서 아무도 갱신하지 않았다.

GitHub Projects(v2) 보드를 얹어 상태·일정·진척률을 한 곳에서 관리한다.

## 단일 소스 원칙

| 정보 | 있어야 할 곳 |
|---|---|
| 작업의 진행 상태 (진행/보류/완료) | **GitHub Projects 보드** |
| 무엇을 왜 만드는가 (설계) | 리포 `docs/superpowers/specs/` |
| 어떤 순서로 만드는가 (계획) | 리포 `docs/superpowers/plans/` |
| 요약과 외부 공유 | 노션 (GitHub 링크만) |

노션 백로그 DB는 **상태를 직접 관리하지 않는다.** 이슈 링크와 한 줄 요약만 남기고,
진행 상태는 보드를 본다. 두 곳에서 상태를 관리하면 반드시 한쪽이 방치된다.

## WBS 계층 구조

```
Level 1  에픽        →  Project의 Epic 필드 (릴리즈 단위: v1.7 여행 정산)
Level 2  기능        →  Issue
Level 3  세부 작업   →  Sub-issue  (상위 이슈에 3/11 형태로 진척률 자동 표시)
```

계획 문서의 `### Task N` 하나가 sub-issue 하나에 대응한다.
Task 안의 `- [ ] Step N`은 이슈로 쪼개지 않고 sub-issue 본문의 체크박스로 둔다.

## Status 필드

```
📋 백로그   아직 하기로 정하지 않음. 아이디어 포함
🔜 예정     이번 릴리즈에 하기로 정함. 아직 시작 안 함
🚧 진행중   작업 브랜치가 있고 커밋이 올라가는 중
⏸️ 보류     시작했거나 예정이었으나 멈춤. Blocked reason 필수
👀 리뷰중   PR 올라감. main 머지 대기
✅ 완료     main에 머지됨
```

**보류(⏸️)를 별도 상태로 두는 것이 이 보드의 핵심이다.** 이슈를 닫지 않은 채 보드에서만
빼두면 "왜 안 닫혔지"가 사라진다. 보류로 옮길 때는 `Blocked reason` 필드에 사유와
재개 조건을 반드시 적는다. 사유 없는 보류는 그냥 방치와 구분되지 않는다.

## 커스텀 필드

| 필드 | 타입 | 용도 |
|---|---|---|
| `Status` | 단일선택 | 위 6단계 |
| `Epic` | 단일선택 | 릴리즈/대분류 묶음 |
| `Blocked reason` | 텍스트 | 보류 사유 + 재개 조건 |
| `Estimate` | 숫자 | 예상 공수(반나절=0.5 단위) |
| `Start date` | 날짜 | Roadmap 뷰 시작점 |
| `Target date` | 날짜 | Roadmap 뷰 종료점 |

## 뷰 구성

- **Board** — Status로 그룹. 매일 보는 기본 화면
- **Roadmap** — Start/Target date 기준 간트. 릴리즈 일정 확인용
- **Table (보류만)** — `Status = ⏸️ 보류` 필터. 주 1회 재개 여부 판단

## 한계와 대응

1. **선후행 의존관계(FS/SS) 필드가 없다.** 진짜 간트의 화살표는 안 된다.
   → 이슈 본문에 `Blocked by #12`로 적는다. 계획 문서의 Task 순서가 사실상 의존 그래프다.
2. **자동 진척률은 sub-issue 개수 기반뿐이다.** 공수 가중 진척률은 없다.
   → `Estimate` 합계를 뷰에서 sum으로 본다.

## 갱신 시점

- 작업 시작할 때 → 🚧 진행중
- PR 올릴 때 → 👀 리뷰중
- 머지될 때 → ✅ 완료 (워크플로로 자동화 가능)
- 하루 이상 손 놓게 되면 → ⏸️ 보류 + 사유 기록

머지 시 자동 완료 처리는 Project Settings → Workflows → "Pull request merged"를 켜면 된다.
