## 1. 현재 상태 요약

MVP 범위(홈 · 카테고리 소비 입력 · 통계 · 설정 · 이월 · 지출 수정)는 구현 완료. 2026-07-08 다크모드 입력 버그 수정과 홈 기록 버튼 탭 전환까지 반영된 상태. 남은 것은 **출시 준비 항목**과 **후속 개선 기능**이다.

## 2. 우선순위 정리

### P0 — 출시 차단 요소 (App Store 제출 전 필수)

#### 2-1. 개인정보처리방침 / 이용약관 초안
- App Store 심사에 개인정보처리방침 URL 필수.
- **핵심 내용**: 모든 데이터는 기기 내 CoreData에만 저장(로컬 온리), 서버 전송 없음, 계정 없음, 수집하는 개인정보 없음, 제3자 제공 없음.
- **작업**: 노션에 초안 작성 → 공개 페이지로 게시 → URL을 App Store Connect에 등록.
- 난이도: Medium (내용은 단순하나 문구 검토 필요)

#### 2-2. 하루 사용 가능 금액 계산 규칙 확정
- ✅ **완료** — [docs/2026-07-08-daily-budget-calculation-rules.md](2026-07-08-daily-budget-calculation-rules.md)로 확정.
- 후속 결정 3건이 남음 (문서 5절): 급여일 말일 처리, 급여일 이월 리셋 여부, 고정비 > 월급 검증.

### P1 — 다음 마이너 업데이트 (v1.1)

#### 2-3. 데이터 내보내기 (백업 1단계)
- 설정의 "데이터 백업 (준비 중)"을 **CSV 내보내기**로 우선 구현.
- 범위: 소비 기록 전체(날짜/카테고리/내용/금액)를 CSV 생성 → `ShareLink`로 공유(파일 저장·메일 등).
- 원래 참고했던 Numbers 스프레드시트 구조(4컬럼)와 동일해 사용자 친화적.
- iCloud 자동 동기화(CloudKit)는 스키마·충돌 처리 부담이 커서 **v1.2 이후로 분리**.
- 난이도: Low~Medium

#### 2-4. 피드백 보내기
- 설정의 "피드백 보내기 (준비 중)"을 `mailto:` 링크로 구현 (앱 버전·기기 정보 자동 포함).
- 난이도: Low — 빠른 완성 가능.

### P2 — 백로그 (v1.2+)

#### 2-5. 자주 쓰는 항목 즐겨찾기
- 최근/자주 입력한 (카테고리, 내용, 금액) 조합을 소비 입력 화면 상단에 칩으로 노출 → 탭 한 번으로 채움.
- 별도 엔티티 없이 기존 SpendingRecord 집계(빈도 기준 상위 N개)로 구현 가능 → 스키마 변경 불필요.
- 난이도: Medium

#### 2-6. 다크 테마 정식 지원 여부
- **권고: 당분간 라이트 고정 유지** (2026-07-08 `.preferredColorScheme(.light)` 적용).
- 정식 지원하려면 디자인 토큰 전체를 Assets 컬러셋(라이트/다크 변형)으로 이관해야 함 — 비용 대비 우선순위 낮음.
- 사용자 요청이 쌓이면 v1.2에서 재검토.

## 4. 결정 필요 사항

1. **CSV 내보내기 범위**: 소비 기록만 vs 예산 설정·이월 내역 포함 → *제안: 소비 기록만 (단순하게)*
2. **피드백 수신 주소**: 개발자 이메일 확정 필요
3. **급여일 말일 보정 규칙**: 급여일 31일 설정 + 30일까지인 달 → 그 달 말일로 보정할지 → *제안: 말일 보정*
