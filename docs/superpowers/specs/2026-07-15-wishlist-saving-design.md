## 1. 컨셉

사고 싶은 물건을 등록하고, **하루 저금액을 정해 매일 "오늘 쓸 수 있는 금액"에서 가상으로 떼어 모으는** 기능. 실제 통장 이동 없이 앱 안에서만 관리되며, 게이지와 D-day로 "언제 살 수 있는지"를 보여준다.

- 예: 100,000원짜리 물건 + 하루 5,000원 저금 → **D-20**, 매일 게이지가 5,000원씩 차오름.

## 2. 확정된 설계 결정

| 결정 사항 | 선택 |
|---|---|
| 저금 재원 방식 | **고정 일일 저금액** (아이템 활성화 시 하루 저금액 설정) |
| 동시 저금 개수 | 위시 목록은 여러 개, **활성 저금은 1개** |
| 구매 완료 처리 | **완료 처리만, 소비 기록 생성 없음** (이중 차감 방지) |
| 잔액 음수인 날 | **저금 무조건 계속** (D-day 고정, 예측 가능) |

## 3. 핵심 규칙

### 3-1. 등록·활성화

- 위시 아이템: 이름, 목표 금액, (선택) 메모/링크. 여러 개 등록 가능.
- 그중 **1개만 "저금 중"으로 활성화** 가능. 활성화 시 하루 저금액을 설정한다.
- 나머지 아이템은 "대기" 상태로 목록에만 존재한다 (차감 없음).

### 3-2. 일일 저금 (핵심 메커니즘)

- 활성 아이템이 있으면 매일 하루 저금액만큼 차감:

```
오늘 가용 금액 = 기본 일일 예산 + 이월 합계 − 오늘 소비 합계 − 오늘 저금액
```

- 저금은 **소비 기록이 아니며 통계에도 잡히지 않는다.** 오직 오늘 가용 금액 계산에만 등장한다.
- 차감된 저금은 그날 잔액에서 빠진 채로 이월되므로, 누적 저금액은 자연스럽게 "실제로 아껴진 돈"이 된다 (이중 계산 없음).
- 잔액이 음수인 날에도 저금은 **무조건 계속**된다 → D-day가 변하지 않아 예측 가능. 과소비 페널티는 기존 음수 이월 규칙이 반영한다.
- 앱을 며칠 안 열어도 기존 `processDailyBudgets(upTo:)` 일자 체인 생성 시 각 날짜에 저금을 함께 반영한다 (멱등성 유지 — 이미 존재하는 날짜는 건너뜀).

### 3-3. D-day / 게이지

- 남은 일수 = ⌈(목표 금액 − 누적 저금액) ÷ 하루 저금액⌉ → 표시 예: "D-20 · 8월 4일 구매 가능"
- 게이지 = 누적 저금액 ÷ 목표 금액 (%).
- 마지막 날은 남은 잔액만 차감한다 (목표 금액 초과 저금 없음).

### 3-4. 달성·구매 완료

- 누적액이 목표 금액에 도달하면 자동으로 저금이 중지되고 "구매 가능" 상태로 전환된다.
- 사용자가 "구매 완료" 처리하면 히스토리(달성 목록)로 이동한다. **소비 기록은 생성하지 않는다** — 이미 매일 차감으로 모은 돈이므로 이중 차감을 방지한다.

### 3-5. 중도 변경·해지

- **하루 저금액 변경**: 다음 날부터 적용, D-day 재계산 (당일분은 유지).
- **저금 해지(또는 아이템 삭제)**: 모인 누적액을 오늘 잔액으로 환급한다 (이월 항목으로 +누적액). 돈이 증발하지 않는다.
- **활성 아이템 교체**: 해지(환급) 후 새 아이템 활성화. 누적액 이전은 v2에서 고려한다.

## 4. 데이터 모델 (CoreData)

- 새 엔티티 `WishItem`: id, title, targetAmount, dailySaving, status(대기/저금중/구매가능/완료), createdAt, activatedAt, completedAt
- 새 엔티티 `WishSavingEntry` (일자별 저금 기록): date, amount, wishItem 관계
  - 누적액은 entry 합계로 계산한다. 일자별 기록이 있어야 멱등 처리·환급·게이지 히스토리가 정확해진다.
- `DailyBudgetModel.todayAvailable` 계산에 그날의 저금 합계 차감을 추가한다.

### 검토했던 대안

| 대안 | 기각 사유 |
|---|---|
| 가상 소비 기록(SpendingRecord)으로 처리 | 소비 통계 오염, "저금은 소비가 아니다" 원칙 위배 |
| `WishItem`에 누적액 필드만 저장 | 일자별 멱등 처리 불가, 환급·게이지 히스토리 계산 취약 |

## 5. UI 구성

- **홈 화면**: 활성 저금이 있을 때 카드 1개 추가 — "🎁 에어팟 · D-13 · ▓▓▓░░ 35%" + "오늘 −5,000원 저금 중" 표시. 오늘 가용 금액 아래에 저금 차감이 보이도록 한다.
- **위시리스트 화면**: 설정 또는 홈에서 진입 (탭 추가 없음). 아이템 목록(대기/저금중/달성), 추가/편집, 활성화 시 하루 저금액 입력 + "D-○○, ○월 ○일 구매 가능" 미리보기.

## 6. 엣지 케이스

| 케이스 | 처리 |
|---|---|
| 하루 저금액 ≥ 기본 일일 예산 | 활성화 시 경고 표시 (막지는 않음) |
| 목표 금액 도달 직전 마지막 날 | 남은 잔액만 차감 |
| 활성 저금 중 예산 설정 변경 | 저금액은 그대로, 기본 예산만 재계산 (기존 규칙과 동일) |
| 과거 날짜 소비 수정 | 저금 entry는 불변 — 이월만 기존 규칙대로 재계산 |
| 급여일 경계 | 저금은 급여 기간과 무관하게 연속 |

## 7. 범위 제외 (v2+)

- 여러 아이템 동시 저금
- 활성 아이템 교체 시 누적액 이전
- 남은 잔액 수동 추가 저금 (이월 잔액 → 위시 아이템 밀어넣기)

## 8. 희망/필수 구분 (#3, 2026-07-29 추가)

사용자 아이디어 — "희망하는 것과 사야 되는 것을 구분". 위시 아이템에 종류 축을 추가한다.

- `WishItem.kind`: `희망(want)` / `필수(need)`. 기본 `희망`.
- `WishKind` enum(이모지 💖/🎯, 라벨). 목록/카드에 뱃지로 표시.
- 저금 메커니즘·D-day·게이지는 종류와 무관하게 동일. 종류는 분류/표시 축이며, 향후 정렬·우선순위 차등에 활용 가능(현재는 표시).

## 9. 구현 결과 (2026-07-29)

- **데이터**: `WishItem`(id/title/targetAmount/dailySaving/status/kind/createdAt/activatedAt/completedAt) + `WishSavingEntry`(date/amount, WishItem·DailyBudget 관계). `DailyBudget.wishSavingEntries` 관계로 `DailyBudgetModel.todayAvailable`에서 그날 저금 차감.
- **저금 메커니즘**: `applyWishSaving(on:)`을 `processDailyBudgets`·`fetchOrCreateTodayDailyBudget` 생성 지점에 훅. 멱등(일자당 1회), 목표 도달 시 남은 금액만 저금 후 `구매가능` 전환, 활성화일 이전 소급 방지.
- **환급**: 해지/삭제 시 "오늘 이전 저금 합계"를 오늘 이월(+)로 환급, 오늘 엔트리는 삭제로 자연 환급(이중 환급 방지).
- **UI**: 홈 활성 저금 카드(진행률·D-day·오늘 저금액), 위시리스트 화면(저금중/구매가능/대기[희망·필수]/완료 섹션, 추가·수정·저금시작·해지·구매완료·삭제), 설정 진입점.
- **테스트**: `WishListTests` 9개 — 생성/종류, 활성화·일일 저금·가용액 차감, 멱등, 단일 활성 강제, 목표 캡·구매가능 전환, 해지 환급, 완료(소비기록 없음), 삭제 환급.
- **관련 코드**: `Models/WishModels.swift`, `Core/CoreDataManager.swift`, `Features/Wishlist/`, `Features/Home/`.
