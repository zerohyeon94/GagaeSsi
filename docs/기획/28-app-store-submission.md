# App Store 제출 준비 (#28)

작성일: 2026-11-03

코드로 할 수 있는 것은 이 문서와 함께 끝냈고, 나머지는 App Store Connect에서 직접 입력한다.
아래 문구는 **초안**이다 — 그대로 붙여 넣어도 되지만 톤은 다듬어도 된다.

## 1. 코드에서 끝낸 것

| 항목 | 내용 |
|---|---|
| 개인정보 매니페스트 | `GagaeSsi/App/PrivacyInfo.xcprivacy` — 추적 없음, 수집 데이터 없음, 필수 사유 API 사용 없음 |
| 수출 규정(암호화) | `ITSAppUsesNonExemptEncryption = NO` — 업로드마다 묻는 암호화 질문을 건너뛴다. 앱은 네트워크·자체 암호화를 쓰지 않는다 |
| 앱 용량 | 쓰지 않던 폰트 13MB 제거 (#25) |
| 버전 | `1.0 (1)` — 규칙은 `docs/기획/29-store-version-rules.md` |

필수 사유 API(UserDefaults, 파일 타임스탬프, 시스템 부팅 시각, 디스크 용량, 키보드 목록)는 코드에서 쓰지 않는 것을 확인했다.
나중에 `@AppStorage`·`UserDefaults`를 쓰게 되면 `NSPrivacyAccessedAPITypes`에 `NSPrivacyAccessedAPICategoryUserDefaults`(사유 `CA92.1`)를 추가해야 한다.

## 2. 막혀 있는 것

- **문의 이메일 (#26)** — 정해지면 `FeedbackMail.supportEmail`, App Store Connect 지원 이메일, 개인정보처리방침 문의처를 같은 주소로
- **법무 문서** — 노션 개인정보처리방침·이용약관의 `[입력해 주세요]`(개발자명·문의 이메일) 채우기 → 노션 Publish로 공개 URL → (권장) 변호사 검토

### 키워드 (100자, 쉼표 구분, 공백 없이)

```
가계부,하루예산,용돈,예산,지출,소비,절약,월급,고정비,이월,돼지,여행정산,더치페이,저금,위시리스트
```

### 프로모션 문구 (170자)

```
월급과 고정비만 넣으면 오늘 쓸 수 있는 돈을 알려줘요. 남은 돈은 내일로 넘어가고, 많이 쓴 날은 가계씨가 표정으로 알려줘요.
```

### 설명

```
"오늘 얼마 쓸 수 있어?"

가계씨는 월급, 고정비, 급여일만으로 하루에 쓸 수 있는 금액을 계산해 주는 가계부예요.
복잡한 분류나 통계보다, 지금 이 순간 쓸 수 있는 돈 하나에 집중했어요.

■ 오늘 쓸 수 있는 돈
• (월급 − 고정비) ÷ 급여 기간 일수로 하루 예산을 계산해요
• 아낀 돈은 다음 날로 넘어가고, 많이 쓴 날은 다음 날 예산에서 빠져요
• 급여일이 주말이면 실제 입금일에 맞춰 기간을 조정해요

■ 기록은 가볍게
• 금액과 항목만 넣으면 끝. 자주 쓰는 항목은 자동완성돼요
• 지난 날짜 소비도 나중에 넣으면 그 뒤 예산이 다시 계산돼요
• 카테고리를 직접 만들고 고칠 수 있어요

■ 같이 쓴 돈, 모아 쓰는 돈
• 여행: 같이 쓴 돈은 내 몫만 예산에서 빼고, 남의 몫은 여행이 끝나면 한 번에 정산해요
• 위시 지갑: 사고 싶은 것을 위해 매일 조금씩 모으고, 모은 돈으로 쓴 건 예산에서 빠지지 않아요
• 페이백·할부도 따로 챙겨요

■ 초과해도 괜찮아요
• 크게 넘겨 쓴 날은 갚을 계획을 세워 며칠에 나눠 갚을 수 있어요
• 지난 초과 기록을 모아 볼 수 있어요

■ 내 데이터는 내 기기에만
• 회원가입도, 서버도 없어요. 모든 기록은 이 기기에만 저장돼요
• 원하면 CSV로 내보낼 수 있어요

■ 그 밖에
• 다크 모드 · 기록 리마인더 알림 · 시간대별 소비 리포트
```

> 설명에 쓴 기능은 모두 develop 기준으로 들어 있는 것이다. 빠진 기능이 생기면 설명에서도 지운다 (심사 2.3.1 — 없는 기능 광고 금지).

### 스크린샷

`AppStoreScreenshots/`의 세트를 쓴다.

| 기기 | 폴더 |
|---|---|
| iPhone 6.9" | `iPhone-6.9` 또는 `iPhone-6.9-Marketing` |
| iPad 13" | `iPad-13` 또는 `iPad-13-Marketing` |

앱이 iPad도 지원(`TARGETED_DEVICE_FAMILY = 1,2`)하므로 **iPad 스크린샷이 필수**다. 스크린샷이 스타일 가이드(`docs/디자인/6-brand-style-guide.md`)의 팔레트와 현재 화면을 따르는지 올리기 전에 확인한다 — 여행·사용자 카테고리 이전에 찍은 것이면 다시 찍는다.

### 앱 개인정보 (App Privacy)

- **데이터 수집 여부: "아니요, 이 앱에서 데이터를 수집하지 않습니다."**
- 근거: 네트워크 통신·분석 SDK·광고·계정이 없고 모든 데이터는 기기 로컬 CoreData에 있다.
- "피드백 보내기"는 사용자가 매번 직접 메일 앱으로 보내는 선택 기능이라 수집으로 신고하지 않아도 된다 (Apple 기준: 선택적이고 사용자가 매번 직접 제공하는 경우).

## 4. 제출 순서

1. #26 주소 확정 → 코드 한 줄 교체 PR
2. 법무 문서 공개 URL 확보
3. `CURRENT_PROJECT_VERSION` 확인 (첫 업로드는 1)
4. Xcode › Product › Archive (Release) → Distribute › App Store Connect 업로드
5. TestFlight 내부 테스트로 설치해 #27 실기기 절차 수행
6. 위 입력값 채우고 심사 제출 → 제출한 커밋에 `store/1.0` 태그
