# 실기기 검증 절차 (#27)

작성일: 2026-11-03

#27 체크리스트를 **자동 테스트가 이미 잡는 것**과 **실기기에서만 볼 수 있는 것**으로 나누고,
실기기 항목은 따라 하기만 하면 되는 절차로 적는다. 여기서 나온 버그는 별도 이슈로 쪼갠다.

## 1. 자동 테스트가 이미 잡는 것

계산이 맞는지는 아래 테스트가 매번 확인한다. 실기기에서는 **화면에 그 숫자가 그대로 보이는지**만 본다.

| 체크리스트 항목 | 테스트 |
|---|---|
| 며칠 미실행 후 소급 처리·이월 연결 | `MissingDayBackfillTests`, `CombinedScenarioTests` |
| 급여일 주말 보정(±2일)·말일 클램프·2월 | `DailyBudgetCalculatorTests` (`testEffectivePayday_*`, `testPayPeriod_*`) |
| 급여일 부채 흡수 | `DebtRepaymentTests`, `DebtTimelineTests`, `PastOverspendConversionTests` |
| 모델 1 → 13 lightweight migration, 기존 금액 보존 | `CoreDataMigrationTests` (디스크 SQLite 스토어로 실제 마이그레이션 경로를 탄다) |
| 위시 지갑 + 여행 분담 + 미실행 + 급여일이 겹친 이월 체인 | `CombinedScenarioTests` |
| 두 렌즈 (통계 `myShareTotal` / 초과 판정 `budgetOutflow`) | `CategorySpendingTests`, `OverspendHistoryTests`, `TripSettlementTests` |
| 과거 날짜 소비 추가·수정·삭제 후 이월 재연결 | `PastSpendAutoRecalcTests`, `CombinedScenarioTests` |
| 알림 예약 날짜·식별자(`vcost-`·`spend-`·`payback-`) | `NotificationSchedulingTests`, `SpendReminderTests` |
| CSV 내용(BOM·이스케이프·기간) | `DataExportTests` |

> 인메모리 스토어는 마이그레이션 경로를 타지 않지만, `CoreDataMigrationTests`는 버전별 모델로 디스크 스토어를 만든 뒤
> 현재 모델로 여는 방식이라 그 경로를 탄다. 실기기에서 남는 위험은 **실제 사용자 데이터 양과 파일 보호 상태**뿐이다.

## 2. 실기기에서만 볼 수 있는 것

### 준비

1. **App Store에 나갈 빌드와 같은 구성**으로 설치한다 (Release 구성 또는 TestFlight).
2. 지금 쓰던 앱을 지우지 말고 **덮어 설치**한다 — 마이그레이션은 기존 데이터가 있어야 탄다.
3. 설치 전에 설정 › 데이터 내보내기로 CSV를 하나 받아 둔다. 마이그레이션 후 금액 비교의 기준이다.

### A. 마이그레이션 (가장 먼저)

- [ ] 덮어 설치 후 첫 실행에서 앱이 뜬다 (스토어를 못 열면 `fatalError`로 바로 꺼진다)
- [ ] CSV를 다시 내보내 설치 전 CSV와 비교 — 금액·날짜·항목 수가 같다. 여행 이전 기록의 `인원`은 1, `내 몫`은 결제 금액 그대로다
- [ ] 홈의 오늘 금액이 설치 직전에 본 금액과 같다

### B. 시간이 지나야 보이는 것 — 기기 날짜를 옮겨서

설정 › 일반 › 날짜 및 시간 › **자동으로 설정 끄기** 후 날짜를 바꾼다. 끝나면 반드시 다시 켠다.

> ⚠️ 날짜를 앞으로 옮겼다가 되돌리면 그 사이 만들어진 일자 데이터가 남는다. **테스트용 기기나 데이터로** 하고,
> 실사용 데이터로 하려면 A의 CSV를 백업으로 둔다.

- [ ] **며칠 미실행:** 오늘 소비 하나 입력 → 앱 종료 → 날짜를 3일 뒤로 → 앱 열기. 홈의 이월이 사이 날들을 거쳐 이어지는지 (내역에서 빈 날이 생겼는지 확인)
- [ ] **급여일 통과:** 급여일 전날로 맞추고 예산을 크게 넘겨 쓴다 → 급여일로 옮겨 앱 열기. 오늘 금액이 새 기간 예산으로 바뀌고 부채가 줄었는지. 분리 모드로 모아둔 이월금이 있으면 "급여일이에요 🎉" 확인(3-12)이 뜨는지
- [ ] **주말 급여일:** 급여일이 토·일인 달로 옮겨, 그 전 금요일에 새 기간 예산으로 바뀌는지
- [ ] **말일 급여일:** 급여일을 31일로 두고 2월 말로 옮겨, 2월 28(29)일에 기간이 바뀌는지

### C. 알림

- [ ] 소비 리마인더를 2분 뒤로 설정 → 앱을 백그라운드로 → 알림이 뜬다
- [ ] 변동 고정비 지출일·페이백 수령 예정일을 오늘로 둔 항목을 만들고 알림 시각에 뜨는지
- [ ] 설정 앱에서 가계씨 알림을 **끈 상태**로 위 설정을 바꿔도 앱이 멈추거나 오류 없이 저장된다

### D. 화면

- [ ] 제어 센터에서 라이트/다크를 오가며 소비 입력의 TextField 글자가 읽힌다. 앱 설정의 테마(밝게/어둡게)도 각각
- [ ] 설정 › 손쉬운 사용 › 디스플레이 및 텍스트 크기 › 더 큰 텍스트를 최대로 — 홈 카드 금액, 소비 입력 금액, 통계 합계가 잘리거나 `…`로 줄지 않는다
- [ ] 설정 › 데이터 내보내기 → 공유 시트가 뜨고, 파일 앱에 저장·메일 첨부가 된다. 받은 CSV를 Numbers/Excel로 열어 한글이 깨지지 않는다
