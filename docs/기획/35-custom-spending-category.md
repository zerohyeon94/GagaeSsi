# 기획: 사용자 카테고리 추가 (#35)

- 대상 기능: 가게씨 - 소비 기록과 과거 내역
- 변경 유형: 기능 변경 (feature_change)
- 작성: 기획팀, 2026-10-29

## 1. 누구의 어떤 문제인가

소비를 기록하는 사용자는 지금 카테고리를 7개(식비·교통·카페·쇼핑·의료·여가·기타) 중에서만 고를 수 있다
(`SpendingCategory` enum, `Common/DesignSystem.swift`). 생활마다 자주 쓰는 지출은 다르다.
반려동물, 육아, 경조사, 구독, 미용, 술자리 같은 지출은 맞는 칸이 없어서 대부분 "기타"로 들어간다.

그 결과:
- **통계가 쓸모를 잃는다.** "카테고리별 지출"에서 기타가 크게 잡혀도 그 안에 무엇이 있는지 모른다.
  통계 화면이 해야 할 "어디에 많이 썼나" 질문에 답하지 못한다.
- **페이백 자동 묶기가 막힌다.** 기간형 페이백은 카테고리로 소비를 묶는다(`linkedCategory`).
  자기 지출에 맞는 카테고리가 없으면 기타 전체가 묶이거나 수동으로 더해야 한다.
- 기록할 때마다 "이건 어디에 넣지?" 고민이 생긴다. 앱의 약속인 빠른 기록에 마찰이 된다.

요청 원문의 "다양한 상황"은 사람마다 필요한 칸이 다르다는 뜻으로 읽었다.
그래서 내장 카테고리를 몇 개 더 늘리는 방법 대신 **사용자가 자기 카테고리를 직접 만드는 기능**으로 정한다.
카테고리를 몇 개 늘려도 누군가의 "기타" 문제는 그대로 남기 때문이다.

## 2. 목표

- 사용자가 자기 생활에 맞는 카테고리를 만들어 기록·수정·통계·페이백에서 내장 카테고리와 똑같이 쓴다.
- 카테고리를 바꾸거나 지워도 과거 기록, 통계, 예산·이월 계산이 깨지지 않는다.

## 3. 이번에 할 것 (In Scope)

1. **카테고리 관리 화면 신설** — 설정 > "데이터" 섹션, "항목 이름 정리" 위에 "카테고리 관리" 행을 추가한다.
   - 위쪽: 내장 카테고리 7개 목록(읽기 전용, "기본" 표시)
   - 아래쪽: 내가 만든 카테고리 목록 + "카테고리 추가" 버튼
2. **추가** — 이름(필수), 이모지(필수, 기본값 💸 또는 추천 목록에서 선택), 색상(정해 둔 팔레트 중 선택)을 입력한다.
3. **수정** — 사용자 카테고리의 이름·이모지·색상을 바꾼다. 이름을 바꾸면 그 카테고리의 과거 기록과
   페이백 연결도 새 이름으로 보인다(기록마다 다시 고치지 않아도 된다).
4. **삭제** — 사용자 카테고리를 지운다. 쓰던 기록이 있으면 "기록 N건은 기타로 옮겨져요"라고 확인을 받은 뒤
   그 기록과 그 카테고리에 묶인 페이백을 "기타"로 옮긴다.
5. **노출 위치 반영** — 아래 모든 곳에서 내장 7개 뒤에 사용자 카테고리가 만든 순서대로 이어서 나온다.
   - 소비 기록(`SpendView`) 카테고리 칩, 내역 수정(`HistorySpendEditView`) 칩
   - 내역·소비 기록 목록 행의 이모지·색 원, 여행 상세·초과 내역 행
   - 통계 "카테고리별 지출" 행·차트 색, `CategoryDetailView`
   - 페이백 기간형 "묶을 카테고리" 칩, 페이백 목록의 연결 표시
   - 자동완성 추천 칩의 이모지, CSV 내보내기 "카테고리" 열(현재 이름으로)
6. **데이터 초기화 연동** — "데이터 초기화" 시 사용자 카테고리도 함께 지운다.

## 4. 이번에 하지 않을 것 (Out of Scope)

| 항목 | 이유 |
|---|---|
| 내장 카테고리 7개의 이름 변경·삭제·숨기기 | 기본 분류와 "기타" 대체 규칙의 기준이라 고정한다. 숨기기 요구가 생기면 다음 과제로 본다 |
| 카테고리 순서 바꾸기(드래그 정렬) | 첫 버전은 만든 순서로 충분하다. 써 보며 요구가 생기면 추가 |
| 하위 카테고리(2단계 분류) | 기록 마찰이 커진다. 문제(기타 쏠림)는 1단계로 풀린다 |
| 카테고리별 예산 한도·알림 | 이 앱의 예산은 "하루 사용 가능 금액" 하나다. 계산 규칙 문서 변경이 필요한 별도 기획 |
| 고정비·할부·위시·여행 자체에 카테고리 붙이기 | 지금도 카테고리가 없는 대상이다. 이번 범위는 소비 기록(SpendingRecord)과 그것을 쓰는 화면만 |
| 기존 기타 기록을 새 카테고리로 일괄 옮기기 | 있으면 좋지만 범위가 커진다. 이번엔 내역 수정에서 한 건씩 바꾼다. 다음 과제 후보 |

## 5. 사용자 흐름

### 5-1. 진입
- 설정 탭 > 데이터 > **카테고리 관리** → 관리 화면.
- 소비 기록 화면 카테고리 칩 줄 끝에 **"+ 추가"** 칩을 둔다. 탭하면 추가 시트가 뜨고,
  저장하면 방금 만든 카테고리가 선택된 채로 기록 화면에 돌아온다(기록 흐름을 끊지 않기 위해서).

### 5-2. 추가
1. "카테고리 추가" → 시트: 이름 입력 → 이모지 선택 → 색상 선택 → 미리보기 칩 → 저장.
2. 저장 버튼은 이름이 유효할 때만 켜진다.
3. 저장하면 목록 맨 뒤에 붙고, 기록·수정·페이백 칩에 바로 나온다(`AppEventBus`로 갱신을 알린다).

### 5-3. 실패
- 이름이 비었거나 공백뿐 → 저장 비활성.
- 이름이 내장 또는 기존 사용자 카테고리와 같음(앞뒤 공백 제거, 대소문자 무시 비교) →
  "이미 있는 카테고리 이름이에요" 안내, 저장 비활성.
- 이름이 10자를 넘음 → 입력을 10자에서 멈춘다(칩이 깨지지 않게).
- 사용자 카테고리가 20개 → "카테고리 추가" 비활성, "카테고리는 20개까지 만들 수 있어요" 안내.
- 저장 실패(CoreData 오류) → 시트를 닫지 않고 "저장하지 못했어요. 다시 시도해 주세요" 표시.

### 5-4. 수정·되돌리기
- 목록에서 사용자 카테고리 탭 → 같은 시트(수정 모드). 취소하면 아무것도 바뀌지 않는다.
- 이름 변경도 위의 중복·길이 규칙을 따른다(자기 자신의 기존 이름은 중복으로 보지 않는다).
- 삭제는 수정 시트 아래 "카테고리 삭제" 버튼 또는 목록 스와이프로 한다. 반드시 확인 다이얼로그를 거친다.
  - 쓰던 기록 0건: "○○ 카테고리를 삭제할까요?"
  - 쓰던 기록 N건: "○○ 기록 N건은 '기타'로 옮겨져요. 삭제할까요?" (묶인 기간형 페이백이 있으면 그 수도 함께 안내)
- 삭제는 되돌릴 수 없다(확인으로 막는다). 같은 이름으로 다시 만들어도 이미 기타로 옮겨진 기록은 돌아오지 않는다고
  다이얼로그에 적는다.

## 6. 완료 기준 (Acceptance)

1. 설정 > 카테고리 관리에서 사용자 카테고리를 만들면, 앱 재시작 없이 소비 기록·내역 수정·페이백 칩에 바로 나온다.
2. 사용자 카테고리로 저장한 기록이 내역·통계(행·차트 색·상세)·CSV에 그 이름·이모지·색으로 나오고,
   앱을 다시 켜도 유지된다.
3. 사용자 카테고리 이름을 바꾸면 과거 기록·통계·페이백 연결이 모두 새 이름으로 보이고 금액 합계는 바뀌지 않는다.
4. 사용 중인 카테고리를 지우면 확인 후 해당 기록·페이백 연결이 "기타"로 옮겨지고, 통계 합계는 바뀌지 않는다.
5. 카테고리 추가·수정·삭제 전후로 홈 오늘 사용 가능 금액, 이월, 예산 장부 값이 같다(예산 계산은 카테고리와 무관).
6. 중복 이름·빈 이름·10자 초과·21번째 추가가 막히고, 추가·수정·삭제·중복 차단·삭제 후 기타 이동·데이터 초기화에
   대한 단위 테스트가 `CoreDataManager(inMemory: true)`로 통과한다. 기존 테스트는 계속 통과한다.

## 7. 예외 상황

- **기존 데이터 호환**: 지금 기록은 카테고리를 한글 이름 문자열로 저장하고, 모르는 값은 기타로 보인다
  (`SpendingCategory.from(rawValue:)`). 업데이트 후에도 기존 기록은 그대로 같은 카테고리로 보여야 한다.
  CoreData 스키마 변경은 lightweight migration 안에서 한다.
- **이름 변경과 문자열 저장**: 기록이 이름 문자열을 들고 있으면 이름을 바꿀 때 옛 기록이 기타로 떨어질 위험이 있다.
  저장 방식(안정적인 ID 참조 또는 이름 변경 시 일괄 갱신)은 개발팀이 정하되, 완료 기준 3을 반드시 만족해야 한다.
- **삭제된 카테고리를 가리키는 데이터**: 자동완성 추천(최근 카테고리), 기록 화면에 선택돼 있던 칩,
  수정 중인 기록이 지워진 카테고리를 가리키면 기타로 보여 준다. 크래시나 빈 칩이 나오면 안 된다.
- **다크 모드·색상**: 사용자가 고르는 색 팔레트는 `Color.adaptive(light:dark:)` 토큰으로 정의해 두 모드에서 모두
  칩 글자가 읽혀야 한다. 뷰에 hex를 박지 않는다. 통계 차트에서 내장 색과 너무 비슷한 색이 겹치지 않도록 팔레트를 고른다.
- **이모지 입력**: 이모지 칸에는 이모지 1개만 들어간다. 여러 글자·일반 문자를 넣으면 첫 이모지만 쓰거나 저장을 막는다
  (어느 쪽이든 칩 모양이 깨지지 않아야 함).

## 8. 우선순위 근거

- 기록 → 통계로 이어지는 핵심 흐름의 품질 문제라서, 출시 후 새 기능보다 먼저 손볼 가치가 있다.
- 순서/하위 분류/카테고리 예산은 "기타 쏠림" 문제를 푸는 데 꼭 필요하지 않아 뺐다.
  특히 카테고리 예산은 계산 규칙 문서(`docs/2026-07-08-daily-budget-calculation-rules.md`)를 바꿔야 해서 별도 기획으로 다룬다.

## 9. 용어

- **내장 카테고리**: 앱이 기본으로 주는 7개. 화면 표기는 "기본".
- **사용자 카테고리**: 사용자가 만든 카테고리. 화면 표기는 "내가 만든 카테고리".
- 화면 문구에서는 기존과 같이 "카테고리"라고 쓴다("분류", "태그"는 쓰지 않는다).
